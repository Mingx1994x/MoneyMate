# 端到端測試資料（fixtures）

- **負責人：** D
- **用途：** A、B 的 Playwright 測試直接登入這些帳號，檢查畫面上的數字（PRD 20.5「端到端測試資料」）。
- **程式：** `backend/src/seed/e2e-fixtures.ts`，測試在 `backend/test/seed-e2e.e2e-spec.ts`。

## 怎麼建立

在 `backend/` 執行（連 `DATABASE_URL` 指的資料庫，本機是 `app_dev`）：

```bash
E2E_PASSWORD=<8 字元以上> npm run seed:e2e
```

- 也可以把 `E2E_PASSWORD=...` 寫在 `backend/.env`，之後只要執行 `npm run seed:e2e`。
- 可以重複執行：每次都先刪掉下面 3 個帳號，再照同樣的內容重建。不會動其他使用者。
- `E2E_PASSWORD` 沒設定或少於 8 個字時直接失敗，原本的帳號不會被刪。
- Playwright 登入時用同一個 `E2E_PASSWORD`。
- 交易日期都是**本月 1 號**：不管哪一天跑，「本月」的數字都一樣。
- 帳號都是 `@moneymate.test`（測試帳號規則）。Demo 前刪除所有測試帳號時會一起刪掉，要再測就重新執行一次。

## 帳號與畫面上應該出現的數字

### 1. `e2e-new@moneymate.test`：還沒做問卷

| 項目 | 內容 |
|---|---|
| 資料 | 只有註冊，沒有目標、帳戶、交易 |
| 登入後 | `hasCompletedOnboarding: false` → 應該被帶到問卷頁 |

### 2. `e2e-dashboard@moneymate.test`：Dashboard 驗算案例（PRD 第二十七節 AC-22）

| 資料 | 內容 |
|---|---|
| 目標 | 每月花費 40,000 → 目標 12,000,000 |
| 帳戶 | 銀行（初始 300,000）、信用卡（初始 0） |
| 貸款 | 房貸未償 1,000,000，`active` |
| 本月交易（1 號） | 薪資收入 50,000（銀行）、生活支出 30,000（信用卡）、房租支出 80,000（銀行）、繳卡費轉帳 10,000（銀行 → 信用卡） |

| 畫面 | 應該顯示 |
|---|---|
| 本月收入／支出 | 50,000／110,000（轉帳不計） |
| 儲蓄率 | −120.0% |
| 銀行／信用卡 | 260,000／−20,000 |
| 帳戶合計 | 240,000 |
| 淨資產 | −760,000 |
| 目標進度 | 2.0% |
| 下一站 | 第 2 站 100 萬，「再存 760,000」 |

> 房租在 AC-22 是一張帳單。帳單繳費（E 的 #78）合併前先記成一般支出，數字一樣；合併後改成帳單，這份文件會跟著更新。

### 3. `e2e-goal@moneymate.test`：目標驗算案例（AC-16）

| 資料 | 內容 |
|---|---|
| 目標 | 每月花費 40,000 → 目標 12,000,000 |
| 帳戶 | 銀行 300,000、信用卡 −50,000 |
| 交易、貸款 | 沒有 |

| 畫面 | 應該顯示 |
|---|---|
| 目前金額 | 250,000 |
| 目標進度 | 2.1% |
| 里程碑 | 第 1 站 10 萬已達成；第 2 站 100 萬「再存 750,000」 |
| 財富自由年齡 | 沒有出生年 → 只問出生年，不顯示年齡（AC-27） |

## 注意

- 數字錯了先看是不是有人在測試時改了這些帳號的資料：重新執行 `npm run seed:e2e` 就會回到上面的內容。
- 要新增其他情境的帳號，請找 D，不要直接改資料庫。
